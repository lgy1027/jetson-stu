# Day 0 + 30 个实践单元

## 课程定位

这是一套面向已有 Python、深度学习或 LLM 应用基础开发者的 Jetson 具身智能转型课程。课程不重复讲解编程入门，而是补齐端侧部署、ROS 2、三维坐标、机器人建模、运动规划、安全约束和系统集成能力。

“Day”只是稳定的课程编号，不代表必须在一个自然日内完成。学习者可以根据安装、编译、实验和排障情况跨多次学习会话完成一个单元。是否进入下一单元只由验收证据决定，不由耗时决定。

## 第一阶段目标

完成一条安全、可复现、可观测的离线机械臂仿真闭环：

```text
自然语言目标
    → 受约束任务 Schema 与技能白名单
    → 图片/视频感知与候选目标
    → 相机模型、模拟深度与 TF2 坐标转换
    → 工作空间、时效性与安全检查
    → MoveIt 运动规划与碰撞检查
    → 仿真可视化、结构化结果与性能评估
```

LLM/VLM 只能参与语义理解、任务分解和技能选择。关节限制、工作空间、碰撞检查、轨迹规划与执行安全必须由确定性逻辑负责。第一阶段不连接真实执行器。

## 学习方式

- Day 0 只建立可重复开发、CUDA 实计算与 GPU 容器基线。
- Day 1–30 是 30 个有先后依赖的实践单元，不设置强制日历进度。
- 每个单元都必须留下代码、配置、命令、原始输出或结构化结果。
- 安装与兼容性检查只为当前实践服务，不预装整套技术栈。
- 已掌握的概念可以快速通过，但验收不能跳过。
- 综合单元可以跨多次学习会话；遇到 ARM64 兼容性问题时先记录和解决，不为追赶编号降低验证标准。

## 六个里程碑

| 里程碑 | 单元 | 能力目标 | 可检查产物 |
|---|---:|---|---|
| M1 可复现感知程序 | Day 1–5 | 在 Jetson 上处理图像、使用 GPU、运行模型并处理视频 | 图像/视频输出、结构化结果、GPU 证据 |
| M2 ROS 2 感知系统 | Day 6–10 | 把离线感知包装成可配置、可回放的 ROS 2 系统 | package、消息契约、launch、rosbag 证据 |
| M3 可验证部署后端 | Day 11–15 | 完成 ONNX、ONNX Runtime、TensorRT 和公平基准 | engine 构建记录、正确性对比、性能与内存数据 |
| M4 有物理含义的目标 | Day 16–20 | 从像素与深度得到三维目标，并建立 TF/URDF/MoveIt 模型 | 相机模型、变换测试、URDF 与 MoveIt 配置 |
| M5 安全任务规划 | Day 21–25 | 规划合法目标、拒绝非法目标，并建立受约束任务状态机 | 轨迹、拒绝测试、Schema、状态机、目标适配器 |
| M6 端到端作品 | Day 26–30 | 集成、测试、测量、复现并展示完整安全闭环 | 端到端 trace、失败矩阵、指标、README 与演示 |

| Day 22 | 非法目标安全拒绝 | 越界、碰撞、不可达和 TF 错误得到结构化原因 |

## 每个单元的课件标准

完整课件按需要包含以下内容，不为命令或动作标注强制完成时间：

1. 本单元目标与工程问题；
2. 前置知识、已有产物和兼容性边界；
3. 完成本单元必需的核心概念；
4. 要构建的数据流或系统边界；
5. 分阶段操作教程、完整源码与配置；
6. 预期结果、错误路径和排障方法；
7. 必做实践与可选挑战；
8. 产物、自动检查或结构化验收；
9. 工程复盘及其与最终项目的连接；
10. 使用到的官方资料和版本说明。

并非每个单元都需要机械复制十个标题；较短课件可以合并相邻部分，但必须让学习者知道前置条件、操作边界、成功证据和失败处理。

## 作品集证据贯穿全程

作品集不是最后一天才补写的文档。每个里程碑结束时都更新：

- 可复现命令和环境信息；
- 架构或数据流变化；
- 原始测量与结论；
- 已知限制和失败案例；
- 当前阶段明确没有覆盖的真实硬件风险。

Day 29 负责从干净终端验证这些材料，Day 30 负责最终演示和边界说明。

## 后续进阶方向

30 个核心单元完成后，再根据目标选择独立进阶路线，不挤占机械臂主线：

- Jetson 部署优化：FP16、INT8、动态 Shape、长稳测试、Zero-copy 与 DeepStream；
- 本地 LLM/VLM：受约束结构化输出、技能选择、模型评测与安全回退；
- 真实机械臂：相机标定、手眼标定、`ros2_control`、控制器、急停与现场安全；
- 移动机器人：只有具备移动底盘并选择该方向时，再学习 SLAM、Nav2 和传感器融合。
