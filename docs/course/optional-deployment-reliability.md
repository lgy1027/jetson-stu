# 可选加深：部署失败不应悄悄发生

## 今天的问题

如何让推理程序在输入、模型和资源异常时给出可行动的失败信息？

## 你要掌握

- 正确性失败、环境失败和性能退化是不同问题。
- 模型输入契约应在运行前验证，而不是让底层报难读的异常。

## 实践

1. 为不存在模型、错误输入尺寸、错误 dtype 和空视频写失败测试。
2. 检查运行时 provider/engine 不可用时的回退或明确退出策略。
3. 为每类错误输出：原因、下一步建议和非零退出码。
4. 确认不会把错误结果误标为低置信度成功结果。

## 产物与验收

- 至少四个失败测试。
- `docs` 中一份运行限制与错误处理说明。

## 复盘

何时应该回退到较慢后端，何时应该直接拒绝运行？
