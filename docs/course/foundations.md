# 入门必读：Jetson 部署与机器人系统概念地图

> 它不是一堂需要打卡的课程，而是 Day 0 之前的共同语言。第一次接触 Jetson、模型部署或机器人软件时，先读这一页，再开始动手。

## 你正在搭建什么

这个学习项目的目标不是“在 Jetson 上跑一次模型”，而是构建一个可复现、可解释、可安全演进的机器人软件闭环：

```text
自然语言目标
  → 受限任务 Schema 与安全检查
  → 图像 / 视频感知
  → ROS 2 消息与 TF 坐标变换
  → 仿真机械臂运动规划
  → 执行结果、日志与性能评估
```

大模型可以帮助理解语义、拆解任务或选择技能；但它不直接产生电机电流、PWM 或未经检查的关节指令。碰撞、工作空间、关节极限和执行许可必须由确定性程序验证。

## 一张分层地图

```text
任务层       LLM / VLM、受限任务 Schema、状态机、安全规则
机器人层     ROS 2、Topic / Service / Action、TF2、URDF、MoveIt 2
推理层       Python、PyTorch（训练/原型）、ONNX、ONNX Runtime、TensorRT
加速层       CUDA、cuDNN、NVIDIA 驱动
系统层       Ubuntu、Jetson Linux（L4T）、JetPack、Docker
硬件层       Jetson 设备、摄像头、机械臂、传感器
```

上层依赖下层，但不需要在第一天把每一层都装一遍。课程会在真正需要某层时再引入它：先建立图像输入输出，再接 ROS 2，再做部署、坐标和规划。

## Jetson、JetPack 与 L4T

- **Jetson**：NVIDIA 的边缘 AI 计算平台。它把 ARM CPU、NVIDIA GPU 和统一内存放在同一设备上，适合把感知和机器人软件放到现场运行。
- **Jetson Linux / L4T**：Jetson 专用的底层 Linux、内核、驱动与板级支持包。L4T 是历史名称，日常可把它理解为“Jetson 的系统与驱动层”。
- **JetPack**：Jetson 的软件发行套件，包含 Jetson Linux，以及 CUDA、cuDNN、TensorRT 等相互匹配的组件版本。装软件前首先确认 JetPack 与 Ubuntu / ARM64 的兼容性，不要只看普通 PC 的教程。

现在不需要查询或背诵具体版本。后续只在安装或运行某个实践确有兼容性风险时，再确认相关软件栈是否匹配，并把当次结论记录在实践产物中。

## GPU 推理与部署组件

- **NVIDIA 驱动**：让操作系统和程序能使用 GPU。`nvidia-smi` 主要反映驱动和运行态，不等同于完整开发工具已安装。
- **CUDA**：GPU 通用计算平台。Python 框架和自定义 CUDA 程序都通过它做并行计算；`nvcc` 才是 CUDA 编译工具链的直接证据。
- **cuDNN**：面向深度学习常见算子的 NVIDIA 加速库，卷积、归一化等通常会使用它。
- **PyTorch**：研究、原型和模型导出的常用框架；不是 Day 1 的前置安装项。
- **ONNX**：模型的交换格式。把“某个框架里的模型”变成有明确输入输出契约的文件，方便后续部署。
- **ONNX Runtime**：运行 ONNX 模型的通用推理引擎。它是 TensorRT 前的正确性和性能基线。
- **TensorRT**：NVIDIA 面向部署的推理优化器与运行时。它会按模型、GPU 和软件栈构建优化引擎；引擎通常应在目标 Jetson 上重建，不要把别的机器生成的引擎直接搬过来。

一个实用顺序是：先让程序正确，再得到 ONNX 契约，再用 ONNX Runtime 建基线，最后才用 TensorRT 优化。性能数据必须来自实际工作负载，而不是空转的系统监控。

## Docker 与 Python 环境

- **Docker**：把程序、依赖和启动方式封装成镜像，减少“你的电脑能跑、我的电脑不能跑”。它不是虚拟机，仍然使用宿主机的 Jetson 内核和 GPU 驱动。
- **NVIDIA Container Runtime**：让 Docker 容器能正确访问 Jetson GPU 的运行时桥梁。Day 0 已验证过 GPU 容器；需要模型运行时再单独使用。
- **Python 虚拟环境**：隔离项目依赖，避免为不同实验把系统 Python 混乱地改来改去。一个项目一个环境，依赖写入可复现的清单。

现在不需要因为“以后可能会用”而安装 PyTorch、CUDA Toolkit、ROS 包或 Isaac ROS。先完成当前课程的最小闭环；每次安装都要回答：它服务于哪个实践目标，兼容哪个 JetPack/ARM64 组合。

## ROS 2：让组件协作的机器人中间件

- **ROS 2**：机器人软件的通信与工具生态。它不是操作系统，也不是控制算法；它负责让感知、规划、记录和可视化等节点协同工作。
- **Node（节点）**：一个职责清晰的进程，例如“读取图像”“做推理”或“发布坐标”。
- **Topic（话题）**：持续的数据流，适合图像、检测结果、状态等“不断发生的消息”。
- **Service（服务）**：短请求—响应，适合一次查询或设置。
- **Action（动作）**：可能耗时、可反馈、可取消的任务，适合运动规划或导航。
- **Rosbag**：把 Topic 数据录下来再回放。它让现场输入变成可复现的离线测试样本。

本课程会在第 2 周开始 ROS 2。先用文件与模拟输入做好感知程序，是为了进入 ROS 2 后把注意力放在接口与数据流，而不是同时排查所有环境问题。

## 空间、模型与运动规划

- **TF2 / Transform（坐标变换）**：描述“这个物体相对于那个参考系在什么位置、什么朝向”。视觉结果只有带上坐标系才可能被机器人可靠使用。
- **URDF**：机器人结构描述文件，表达连杆、关节、尺寸和坐标关系；它不是控制程序。
- **MoveIt 2**：机械臂的运动规划与碰撞检查框架。它可以在仿真中寻找满足约束的轨迹，但真实执行仍需有独立安全边界。
- **仿真优先**：当前没有相机和机械臂，所以先用文件、rosbag 与仿真建立软件闭环；等硬件到位后再替换输入和执行端，而不是推倒重来。

## 现在只要记住的六件事

1. JetPack 是整套兼容性基线；安装前先看 JetPack、Ubuntu、ARM64 是否匹配。
2. CUDA 是计算基础，cuDNN 和 TensorRT 是不同层的深度学习加速能力。
3. ONNX 负责模型契约，ONNX Runtime 建基线，TensorRT 做目标设备优化。
4. Docker 解决可复现环境，不取代 Jetson 宿主机驱动。
5. ROS 2 负责组件协作；TF2、URDF、MoveIt 2 分别解决坐标、模型和运动规划。
6. 语言模型只做语义与任务层；任何物理执行必须经过确定性安全检查。
