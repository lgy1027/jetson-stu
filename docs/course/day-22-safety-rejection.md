# Day 22：让非法目标被拒绝

## 今天的问题

机器人系统如何把“没有规划出来”变成可解释、可测试的安全行为？

## 你要掌握

- 越界、碰撞、不可达、TF 不可用和超时需要不同错误码。
- 拒绝是系统正常功能，不是异常后补救。

## 实践

1. 构造一个工作空间外目标。
2. 构造一个碰撞目标或被障碍物遮挡的目标。
3. 构造一个缺失 TF 的目标。
4. 将每个失败映射为结构化原因，不调用执行接口。

## 产物与验收

- 三类以上拒绝测试。
- `robot_description` 或规划层的安全结果枚举/文档。
- 当前规划安全边界总结。

## 复盘

“规划失败”与“安全拒绝”应如何在用户界面和日志中区分？
