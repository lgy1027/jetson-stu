# Day 28：让端到端系统可观测

## 今天的问题

一次成功或失败的演示，怎样让你和其他人都能定位它卡在哪一层？

## 你要掌握

- 指标不是独立的监控作业；它应围绕真实的感知、规划与拒绝路径。
- 每个任务使用同一个 trace id，并记录输入摘要、耗时、状态和失败码。

## 实践

1. 为 Schema 校验、感知、TF、规划四段记录开始、结束、耗时和结果。
2. 输出一份 JSONL 或 CSV 运行记录，避免把原始大图、视频或模型文件提交 Git。
3. 汇总成功率、各阶段 P50/P95 延迟和失败类别计数。
4. 选择一个慢步骤，解释它是需要优化、缓存、丢帧还是保持原样。

## 产物与验收

- `benchmarks/end_to_end_metrics.csv` 或等价记录。
- 至少三次成功/失败运行的可追踪记录。
- 一段基于数据而非直觉的性能结论。
