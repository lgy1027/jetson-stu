# Day 28：失败案例是安全功能

## 今天的问题

系统在不该行动时，能否以安全、可解释的方式停止？

## 你要掌握

- 成功率没有失败分类时没有意义。
- 安全系统必须覆盖缺失感知、低置信度、TF 异常、越界和规划失败。

## 实践

1. 准备至少五类失败输入：无目标、无效深度、低置信度、过期时间戳、TF 缺失、规划不可达/碰撞。
2. 运行端到端链路，验证每类都停止在正确层。
3. 确认所有失败都不会进入仿真执行步骤。
4. 汇总失败码、原因、恢复建议和测试覆盖率。

## 产物与验收

- `demo/failure-cases.md`。
- 至少五个自动化或可重复失败案例。
- 安全退出结论。
