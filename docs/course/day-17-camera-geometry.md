# Day 17：相机模型、深度与三维点

> 本单元先使用固定相机内参与模拟深度，不要求真实相机。目标是补上“二维检测结果为什么能够或不能够成为机器人目标”的几何桥梁。

## 本单元目标

实现一个可测试的像素反投影程序：给定像素坐标、深度值和相机内参，输出相机坐标系中的三维点；对无效深度、越界像素和不一致单位明确拒绝。

## 为什么需要它

图像分类结果或二维检测框只有像素位置，没有真实空间尺度。机械臂规划需要带单位、时间戳和坐标系的三维目标。直接把检测框中心交给 MoveIt，会丢失深度、相机模型、坐标系和误差来源。

本单元只解决：

```text
像素 (u, v) + 深度 z + 相机内参 K
    → 相机坐标点 (x, y, z)
```

从相机坐标到 `base_link` 的时序变换留到 Day 18 的 TF2 单元。

## 前置条件

- 已完成 Day 16 的坐标变换数学与测试。
- 理解图像宽高、像素坐标和 NumPy 数组。
- 不需要摄像头、机械臂或真实深度图。

## 你要掌握

- 针孔相机模型中的焦距 `fx/fy` 与主点 `cx/cy`。
- 深度值的单位必须明确；毫米和米混用会产生数量级错误。
- 检测框中心不是三维点，必须结合深度或其他几何假设。
- 内参、深度、像素和时间戳都属于目标来源证据。
- 无效、缺失或过期深度应阻断后续规划。

## 要构建的系统

在 `perception/camera_geometry.py` 中实现最小接口：

```python
pixel_to_camera(u, v, depth_m, intrinsics) -> point_xyz_m
```

并通过固定测试数据证明：

1. 主点在给定深度下投影到相机光轴；
2. 左右、上下像素产生方向正确的 `x/y`；
3. 零值、负值、非有限深度被拒绝；
4. 图像范围外的像素被拒绝；
5. 毫米输入不会被悄悄当成米。

## 实践

1. 定义包含图像尺寸、`fx`、`fy`、`cx`、`cy` 和单位说明的相机内参结构。
2. 实现像素与深度到相机坐标三维点的反投影。
3. 用手算样例验证主点和一个非主点像素。
4. 为无效深度、越界像素、非法内参和单位错误编写测试。
5. 保存一组固定输入与结构化输出，供 Day 18 TF2 转换复用。

## 产物与验收

- `perception/camera_geometry.py`。
- `perception/test_camera_geometry.py`。
- 一份固定相机内参与像素/深度样例。
- 数值测试覆盖正确反投影和错误路径。
- 输出明确使用相机 frame 和米制单位。
- 能解释为什么二维框、类别置信度或单个像素都不能独立成为机械臂目标位姿。

## 可选挑战

- 从一张模拟深度图读取检测框中心或局部中位数深度，并比较异常值敏感性。
- 为深度噪声加入简单不确定性估计，但不要把它伪装成抓取姿态。

## 与最终项目的连接

本单元输出的是相机坐标系中的候选三维点。Day 18 将使用 TF2 把它转换到 `base_link`；Day 25 才会把带来源、置信度、时间戳和几何条件的结果适配成候选任务目标。
