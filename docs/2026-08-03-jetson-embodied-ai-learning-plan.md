# Jetson 具身智能 12 周学习实施计划

> **执行说明：** 后续与 Codex 按天执行本计划。每天开始时先确认上一天验收结果，再完成当天任务；不要一次安装整条技术栈。

**目标：** 12 周内完成一个运行在 Jetson AGX Thor 上、由自然语言目标驱动、通过 ROS 2 连接视觉感知与仿真机械臂规划的端到端项目。

**架构：** 前三周建立 Jetson 推理与性能分析能力；中间五周补齐 ROS 2、机器人学和运动规划；最后四周将现有 LLM/VLM 能力接入受约束的机器人技能系统。所有阶段都以可运行产物和验收结果为准。

**技术栈：** JetPack 7.2、Ubuntu 24.04 ARM64、Python、少量 C++、Docker、OpenCV、PyTorch、ONNX、TensorRT、ROS 2 Jazzy、TF2、URDF、RViz、MoveIt 2。

---

## 使用规则

- 每天 3～4 小时，每周六天学习，第七天复盘或休息。
- 每天必须留下一个可检查的产物：命令输出、代码、截图、数据表或笔记。
- 每个实验记录版本、命令、输入、输出、耗时和异常。
- 默认先使用图片和视频文件，不等待摄像头或机械臂。
- `[ ]` 未完成，`[x]` 已完成，`[!]` 阻塞；阻塞时在该项下记录原因。

- [ ] 定义 `detect`、`pick`、`place`、`move_home`、`verify` 等技能。
- [ ] 为每个技能定义输入、前置条件、成功条件和失败状态。
- [ ] 区分语义计划与运动控制。
- [ ] 验收：技能接口不包含自由文本电机命令。

### Day 58：结构化任务Schema

- [ ] 使用JSON Schema或类型模型定义任务计划。
- [ ] 限制允许的动作、对象和参数范围。
- [ ] 为非法字段、缺失字段编写测试。
- [ ] 验收：不合法LLM输出无法进入执行层。

### Day 59：自然语言到任务计划

- [ ] 将用户命令转换成技能序列。
- [ ] 添加对象歧义和目标缺失处理。
- [ ] 准备20条正常与异常测试命令。
- [ ] 验收：结构化输出通过Schema验证且行为符合预期。

### Day 60：规则与模型的边界

- [ ] 把关节限制、工作区、速度、禁止区域放在确定性检查层。
- [ ] 实现任务执行前的安全验证器。
- [ ] 测试提示注入和越权动作请求。
- [ ] 验收：模型不能绕过动作白名单和空间限制。

### Day 61：任务状态机

- [ ] 建立IDLE、PERCEIVE、PLAN、EXECUTE、VERIFY、FAILED状态。
- [ ] 定义超时、重试和人工确认规则。
- [ ] 用假技能完成状态机测试。
- [ ] 验收：每条失败路径都有确定终态。

### Day 62：接入ROS 2

- [ ] 将任务请求、状态和结果映射到ROS 2接口。
- [ ] 使用Action执行长任务并持续反馈。
- [ ] 支持取消任务。
- [ ] 验收：文本命令可以驱动模拟技能完成完整状态流转。

### Day 63：复盘

- [ ] 整理LLM适合与不适合负责的部分。
- [ ] 本周检查点：完成受约束、可取消、可审计的语言任务层。

## 第10周：从视觉目标到抓取位姿

**本周目标：** 建立二维检测结果到仿真三维目标位姿的转换链。

### Day 64：相机模型

- [ ] 学习针孔相机、内参、畸变和外参。
- [ ] 用已知内参完成像素点到相机射线计算。
- [ ] 验证图像中心和边缘像素的方向。
- [ ] 验收：公式、代码和简单几何案例一致。

### Day 65：深度与三维点

- [ ] 使用合成深度图或公开RGB-D样例。
- [ ] 将像素与深度反投影为三维点。
- [ ] 处理无效深度和噪声。
- [ ] 验收：对已知平面数据恢复合理三维坐标。

### Day 66：三维坐标进入TF2

- [ ] 发布相机到机器人基座的模拟外参。
- [ ] 将目标点从camera frame转换到base frame。
- [ ] 检查时间戳和frame_id。
- [ ] 验收：变换结果能在RViz中可视化。

### Day 67：基础抓取位姿

- [ ] 为桌面物体设计自上而下抓取规则。
- [ ] 生成pre-grasp、grasp和retreat三个Pose。
- [ ] 检查桌面高度和工作区。
- [ ] 验收：合法对象产生三个有效位姿，非法对象被拒绝。

### Day 68：MoveIt规划接入

- [ ] 将抓取位姿传给MoveIt。
- [ ] 规划接近、抓取和撤离轨迹。
- [ ] 记录IK和碰撞失败原因。
- [ ] 验收：至少一组模拟目标完成全部规划。

### Day 69：感知失败处理

- [ ] 测试目标不存在、多目标、低置信度和深度缺失。
- [ ] 定义重新感知、询问用户或终止策略。
- [ ] 禁止使用过期检测结果执行抓取。
- [ ] 验收：失败不会自动退化为未经验证的动作。

### Day 70：复盘

- [ ] 画出像素→相机三维点→基座坐标→抓取Pose的链路。
- [ ] 本周检查点：感知结果能够产生可规划的抓取目标。

## 第11周：端到端闭环集成

**本周目标：** 串联语言任务、视觉、坐标变换、MoveIt和状态机。

### Day 71：冻结接口

- [ ] 列出所有节点、Topic、Action、参数和frame。
- [ ] 删除重复或职责不清的接口。
- [ ] 为每个接口写示例输入输出。
- [ ] 验收：接口图与代码保持一致。

### Day 72：Happy Path集成

- [ ] 使用固定场景打通“检测→抓取规划→放置规划”。
- [ ] 暂时使用确定性任务输入，减少同时变量。
- [ ] 保存完整日志。
- [ ] 验收：连续运行三次成功。

### Day 73：接入语言任务

- [ ] 用自然语言选择对象和目标区域。
- [ ] Schema验证后驱动状态机。
- [ ] 在执行前展示最终结构化计划。
- [ ] 验收：至少10条命令按预期规划或安全拒绝。

### Day 74：故障注入

- [ ] 注入目标丢失、TF缺失、IK失败、Action超时和用户取消。
- [ ] 检查状态、日志和恢复动作。
- [ ] 修复不确定或无法退出的状态。
- [ ] 验收：所有故障都有可观察结果且不继续危险执行。

### Day 75：性能分析

- [ ] 测量感知、任务规划、坐标转换和运动规划延迟。
- [ ] 记录CPU/GPU、内存、温度和功耗。
- [ ] 找出最大瓶颈并只优化一项。
- [ ] 验收：形成端到端时延分解表。

### Day 76：重复性测试

- [ ] 用固定输入执行不少于30次。
- [ ] 统计检测成功率、规划成功率和总成功率。
- [ ] 对失败按原因分类。
- [ ] 验收：结果不是只展示一次成功演示。

### Day 77：复盘

- [ ] 整理系统已知边界和真机前必须解决的问题。
- [ ] 本周检查点：端到端软件闭环稳定可重复。
